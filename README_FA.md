# Planner Life OS 7.1

این نسخه، مرحله اول توسعه پلنر فعلی است و بدون حذف داده‌های قبلی روی همان ساختار اجرا می‌شود.

## قابلیت‌های افزوده‌شده در ۷.۱

- تقویم شمسی چندساله و انتخاب «سال کاری»
- حفظ کلید ذخیره‌سازی قبلی برای جلوگیری از حذف اطلاعات
- نسخه‌بندی داده با شناسه `planner-life-os-v7.1`
- مهاجرت خودکار اطلاعات نسخه قبلی
- بکاپ خودکار هفتگی در مرورگر
- امکان ساخت بکاپ محلی در هر زمان
- دانلود و بازیابی فایل JSON
- نگهداری حداکثر ۸ نسخه پشتیبان محلی
- ایجاد بکاپ اضطراری پیش از بازیابی و همگام‌سازی
- ادغام رکوردی اطلاعات دو دستگاه بر اساس زمان آخرین تغییر
- ثبت حذف‌ها با Tombstone برای جلوگیری از بازگشت رکورد حذف‌شده
- فونت Vazirmatn با fallback محلی
- کش آفلاین نسخه جدید

## نکته مهم درباره داده‌های فعلی

کلید LocalStorage نسخه قبلی عمداً تغییر نکرده است. بنابراین کارها، اهداف، عادت‌ها، Inbox و برنامه‌های ثبت‌شده قبلی پس از ارتقا باقی می‌مانند.

در نخستین اجرای نسخه ۷.۱:

1. یک نسخه پشتیبان از داده قبلی در IndexedDB ساخته می‌شود.
2. فیلدهای نسخه جدید بدون حذف اطلاعات اضافه می‌شوند.
3. سال کاری روی سال شمسی فعلی یا سال ذخیره‌شده قرار می‌گیرد.
4. برنامه مجدداً با داده‌های قبلی نمایش داده می‌شود.

## نصب روی GitHub Pages

همه فایل‌ها و پوشه `icons` را در ریشه Repository قرار بده:

```text
index.html
styles.css
app.js
v7.js
supabase-config.js
supabase_setup.sql
manifest.webmanifest
sw.js
README_FA.md
icons/
```

پس از Commit، لینک را با پارامتر نسخه باز کن:

```text
https://basaam68401-spec.github.io/planner1/?v=planner-v7-1
```

در Chrome دسکتاپ یک‌بار `Ctrl + Shift + R` بزن. در آیفون، اگر نسخه قبلی باقی ماند، وب‌اپ را ببند و دوباره باز کن یا داده سایت GitHub Pages را پاک کن.

## بکاپ

دکمه «پشتیبان» در سربرگ سه امکان دارد:

- ساخت بکاپ محلی
- دانلود فایل JSON
- بازیابی از JSON

بکاپ خودکار هفتگی روی همان دستگاه ذخیره می‌شود. برای نگهداری خارج از دستگاه، فایل JSON را دانلود و در فضای امن ذخیره کن.

## Supabase

فایل SQL نسخه قبلی همچنان معتبر است؛ زیرا وضعیت برنامه در ستون JSONB ذخیره می‌شود. نیاز به اجرای SQL جدید نیست.

همگام‌سازی نسخه ۷.۱ تلاش می‌کند آرایه‌های اصلی مانند کارها، Inbox، اهداف و عادت‌ها را بر اساس زمان آخرین تغییر هر رکورد ادغام کند، به‌جای اینکه کل داده یک دستگاه بدون بررسی جایگزین دستگاه دیگر شود.

## بازگشت اضطراری

اگر مشکلی مشاهده شد:

1. از بخش «پشتیبان» یکی از نسخه‌های قبل از ارتقا را بازیابی کن.
2. یا فایل‌های نسخه قبلی را دوباره روی GitHub Pages قرار بده.
3. چون کلید ذخیره‌سازی تغییر نکرده، داده‌های قبلی قابل استفاده می‌مانند.
